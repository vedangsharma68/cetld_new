# Auth proxy boundary

Production requires AUTH_CLIENT_IP_HEADER naming a header overwritten by the trusted reverse proxy, never forwarded from untrusted client input. Vercel must use its verified client-IP header; Docker requires the ingress to overwrite a single address header and prevent direct app access. Missing or ambiguous address fails closed, not a shared victim lockout key. Test environment uses a synthetic constant only. Limiter keys combine flow/client-address/email; successes clear their counter. Account-only global locks are deliberately not used.

Public health endpoint is intentional per brief and exposes dependency availability only, not secrets. JWT maxAge is one hour in this candidate, a documented provisional session duration rather than an existing preference. Server session-version lookup invalidates domain access immediately after revoke; proxy is a coarse front gate, not authorization. New routes are protected by default except exact public allowlist and framework assets.

## Database role and lifecycle contract
The isolated baseline enables RLS with no browser policies. Server queries require a dedicated target-schema owner without FORCE RLS, or an explicitly provisioned BYPASSRLS role. Startup checks all eight target tables and fails closed for unsupported ownership. Do not give this connection to the browser. This is not a production provisioning instruction or permission to weaken the existing production RLS.
Auth entry points delete at most 100 expired rate windows and 100 expired Google challenges per attempt, retaining a one-day grace period. No external scheduler is needed; dormant records are inert until the next auth attempt. Indexes support the expiry lookup. Rate-limit rows contain digests, not email/IP plaintext. Final invite/challenge expiry decisions use database clock_timestamp after row locks, not a Node clock or transaction-start timestamp.

## Open signup revision
Credentials verification uses a random256-bit token stored only as SHA256 plus a password hash and pending profile, expiring in30minutes by database clock. No user/business exists until both token and original password are proven. The emailed token uses a URL fragment, removed client-side before API submission, not a query parameter that enters server access logs. Existing users are never overwritten or automatically provider-linked. Different pending requests for one email have different tokens/password proof; the first valid verified transaction wins under an email advisory lock.
SMTP is an approved configurable transport, not a newly provisioned service. Missing sender returns503 and creates no pending state. Production dependency `cetld-smtp` is an npm alias for patched nodemailer10.6.1 because Auth.js's optional nodemailer peer range currently ends at8; that optional provider is not used. Clean npm ci resolves without ignoring peers. Production audit reports zero vulnerabilities; development Drizzle/esbuild advisories remain.
